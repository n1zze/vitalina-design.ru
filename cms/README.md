# PHP CMS

CMS управляет проектами и содержимым страниц для статического сайта VITALINA DESIGN. Целевая среда: PHP 8.5 и MySQL/MariaDB на shared hosting.

## Локальный запуск

1. Установите PHP 8.5+ с расширениями PDO и MySQL.
2. Скопируйте `cms/config/config.example.php` в `cms/config/config.php`.
3. Заполните DSN, пользователя и пароль базы данных.
4. Запустите локальный сервер из корня проекта:

```bash
php -S 127.0.0.1:8080
```

5. Перед первым использованием выполните:

```bash
php cms/tools/check.php
```

## Подключение MySQL

Импортируйте `cms/database/schema.sql` в пустую базу. Для существующей CMS примените миграции по порядку:

```bash
mysql -u USER -p DATABASE < cms/database/migration-001-pages.sql
mysql -u USER -p DATABASE < cms/database/migration-002-publications.sql
```

Публикационная история хранится в таблице `publication_revisions`.

## Создание администратора

Одноразово выполните из корня проекта:

```bash
php cms/tools/create-admin.php admin@example.com 'пароль-длиной-не-меньше-12'
```

После создания первого пользователя удалите `cms/tools/create-admin.php` с production-сервера. Не храните `cms/config/config.php` в Git или публичном архиве.

## Импорт

1. Откройте `cms/admin/import.php` и импортируйте существующие проекты и изображения.
2. Откройте `cms/admin/import-pages.php` и импортируйте `about`, `service` и `contact`.
3. Проверьте проекты и страницы в админке.

## Редактирование

- `cms/admin/project.php` редактирует название, slug, описание, SEO, статус, порядок и изображения проекта.
- `cms/admin/page.php` редактирует управляемый HTML между CMS-маркерами.
- Для проекта используйте только slug из строчных латинских букв, цифр и дефисов.
- Перед публикацией у опубликованного проекта должны быть cover и хотя бы одно существующее изображение.

## Preview

В списке проекта используйте preview перед публикацией. Preview читает данные CMS и не изменяет production-файлы.

## Публикация

1. Убедитесь, что `php cms/tools/check.php` не показывает проблем с путями и базой.
2. Откройте `cms/admin/publish.php`.
3. Добавьте комментарий публикации и нажмите «Опубликовать».

Publisher сначала создаёт пакет в `storage/publish/`, проверяет HTML, CMS-маркеры и изображения, затем сохраняет текущие production-файлы в `storage/backups/`. Только после успешных проверок файлы заменяются. Ошибка до замены не меняет опубликованный сайт.

HTML-каталога и проектов собирается шаблонами в `cms/templates/`. Шаблоны не обращаются к базе и не записывают файлы.

## История и rollback

Откройте `cms/admin/publications.php`, чтобы увидеть:

- ID и дату публикации;
- пользователя;
- статус;
- число файлов;
- комментарий или безопасное описание ошибки.

Кнопка «Вернуть» восстанавливает все файлы выбранной успешной публикации из её backup. Операция выполняется только через POST с CSRF-токеном и записывается как отдельное событие.

## FTP-деплой

На shared hosting передайте по FTP код CMS, миграции и публичные файлы. Убедитесь, что `storage/`, `storage/publish/`, `storage/backups/` и `storage/logs/` доступны CMS для записи. `cms/config/config.php` передавайте отдельно и не публикуйте в репозитории.

## Восстановление после ошибки

1. Не повторяйте публикацию, пока не проверили `storage/logs/cms.log`.
2. Если публикация завершилась ошибкой, production-файлы должны остаться прежними.
3. Если публикация была успешной, откройте историю и выполните rollback.
4. Если backup недоступен, остановите изменения и восстановите backup из резервной копии хостинга.

## Проверка CMS

```bash
php cms/tools/check.php
```

Команда проверяет PHP, конфигурацию, базу, таблицы, права записи, assets и CMS-маркеры. Код завершения `0` означает, что все проверки пройдены. Ошибки не выводят DSN, пароль, SQL или stack trace.

## Публичный сервер

Защитите `cms/` HTTPS и, желательно, дополнительным паролем на уровне хостинга. Не размещайте на публичном сервере `config.example.php`, SQL-схемы, тестовые инструменты и исходные секреты.
